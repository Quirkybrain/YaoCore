# YaoCore 用户使用手册

## 1. 系统组成与适用范围

YaoCore 由以下部分组成：

- OpenHarmony/HarmonyOS ArkTS App：配网、设备管理、本地/远程控制和状态展示；
- 正点原子 DNESP32S3M 网关：运行 ESP-IDF 固件，负责 BLE 配网、家庭 WLAN、本地接口、IoTDA MQTTS 和设备数据转发；
- 家居设备：门锁驱动与门磁、PWM 灯、SHT30、PIR、空调 UART 下位机；
- 可选华为云 IoTDA：手机不在家庭网络时的远程控制和设备影子。

当前网关运行 ESP-IDF，并不是 OpenHarmony 网关；OpenHarmony/HarmonyOS 适配位于 App HAP。源码或静态测试通过不代表外设已经可用，实际部署前必须完成整套实物联调和验收。

## 2. 使用前准备

### 2.1 硬件

- 正点原子 DNESP32S3M/ATK-MWS3S 开发板；
- 支持 2.4 GHz Wi-Fi 的家庭路由器；
- OpenHarmony/HarmonyOS 测试手机或平板；
- 按需接入门锁驱动、门磁、MOSFET 调光灯、SHT30、PIR 和空调下位机；
- 与负载匹配的独立电源、驱动和保护器件。

ESP32 GPIO 只能接逻辑输入或驱动模块控制端，不能直接接门锁线圈、电机、继电器线圈和大功率灯具。所有模块共地、电平和供电必须按原理图核对。

### 2.2 软件与安全资料

- ESP-IDF 5.2.x（项目推荐 5.2.5；当前工程不支持直接用 Arduino IDE 编译）；
- 与目标设备版本兼容的 OpenHarmony SDK、DevEco Studio/Hvigor；
- 每台网关独立的 BLE PoP，8～64 UTF-8 字节；
- App 与网关一致的 HMAC 控制密钥，至少 16 字节；
- 使用云端时的 IoTDA `mqtts://` 地址、设备 ID 和设备 Secret，以及 App 所需的受控访问配置。

正式 PoP、HMAC 密钥、Wi-Fi 密码、IAM Token 和 IoTDA Secret 不得写入仓库、PPT、录屏或公开日志。

## 3. 安装 App

发布版本必须使用目标设备对应的 OpenHarmony SDK 清洁构建：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_openharmony.ps1 `
  -OpenHarmonySdkHome <OpenHarmony-SDK目录>
```

脚本只创建隔离构建目录和调用构建工具，不会自动证明 HAP 能安装。找到生成的 HAP 后记录 SHA-256，在目标 OpenHarmony 设备安装、启动并完成权限与功能回归。HarmonyOS API 22 构建属于适配验证，不能代替 OpenHarmony HAP。

## 4. 配置、编译和烧录网关

打开 ESP-IDF 5.2.5 终端：

```powershell
cd gateway/esp32s3m
idf.py fullclean
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p COMx flash monitor
```

在 `YaoCore Gateway` 菜单至少确认：

- 网关 ID 和名称；
- 独立 BLE PoP；
- 与 App 一致的 HMAC 密钥；
- 门、灯、SHT30、PIR、空调 UART 的真实 GPIO、有效电平、频率、地址、波特率和超时；
- 使用云端时，启用 IoTDA 并填写 `mqtts://` URI、设备 ID 和原始 Secret。

开发板丝印 `USB` 的 USB-C 口连接 ESP32-S3 原生 USB，建议优先用于下载；`UART` 口通过 USB 转串口，可用于下载和日志。如果无法进入下载模式，连接 UART 口，按住 BOOT、短按 RESET，开始烧录后松开 BOOT。烧录结束后不要在启动时持续按住 BOOT。

当前固件使用 ESP-IDF 的 Wi-Fi Provisioning、Protocomm、MQTT、HTTP Server、LEDC 和 I2C/UART API，不能把工程文件直接作为 Arduino sketch 烧录。若改用 Arduino，必须重写并重新验证这些协议和驱动，不能认为功能等价。

## 5. 首次启动和 BLE 配网

首次打开 App 且尚未添加真实设备时，首页家庭状态应显示“未添加设备/尚未添加设备”，不会显示虚构的门锁、舒适度或在线状态。

1. 先到“我的/设置 → 安全配置（控制安全）”保存与固件一致的至少 16 位 HMAC 命令密钥。该密钥不会通过 BLE 发送。
2. 给网关上电。NVS 没有 Wi-Fi 凭据时，网关广播 `YaoCore-GW-xxxxxx`。
3. App 进入“设备”页，展开“手机蓝牙配网”，授予蓝牙权限。
4. 点击“搜索附近网关”，选择机身标签/串口日志对应的网关。
5. 输入该网关的 PoP，点击“扫描家庭 Wi-Fi”。
6. 选择网关扫描到的 2.4 GHz SSID；隐藏网络可手动输入。ESP32-S3 不能加入 5 GHz-only SSID。
7. 输入 Wi-Fi 密码并点击“发送配置并连接”。App 会在 Security1 会话内读取网关 ID，再优先对配网返回 IP 做指数退避的 HMAC 认证；身份一致且板载 LED 回传确认后自动保存绑定。
8. 若提示尚未完成身份认证，让手机切换到与网关相同的新家庭 WLAN，再点击“扫描网关”。BLE 入网成功 **不等于绑定完成**，App 不会按名称、MAC 后缀或邻居顺序猜测绑定。

错误 PoP、错误 Wi-Fi 密码、蓝牙权限拒绝或 MTU 协商失败时，App 应显示错误；不要反复快速点击。修正条件后重新扫描/配网。

## 6. 发现并绑定网关与设备

1. BLE 后续自动绑定未完成时，在“设备”页点击“扫描网关”。App 通过 mDNS/UDP 寻找候选网关，并读取 `/discover`；发现广播只能作为候选，不能单独证明网关身份。
2. 选择目标网关并点击“添加网关”。App 只有在命令密钥存在、协议与安全能力字段校验通过且板载 LED 探针得到真实执行回传后才保存绑定。
3. 若提示安全配置缺失，到“我的/设置 → 安全配置（控制安全）”保存与固件一致的 HMAC 密钥，再重新绑定。
4. 绑定网关后点击“扫描设备”，只添加网关实际返回的在线/可识别设备。
5. “手动录入”只创建待绑定离线占位；占位不会立即可控，必须再次发现同一真实设备并绑定。

若网关 IP 改变，使用“重新查找网关”，不要长期手工固定旧 IP。

切换网关后，旧自定义场景不会按相同 `deviceId` 自动套用到新网关。场景页会要求删除旧动作并从当前网关重新选择；旧版本未记录网关 ID 的场景也必须编辑并重新保存。场景执行中若第 N 项失败，App 会明确显示已完成项数、失败项、后续未执行项及“已执行动作未自动回滚”。

## 7. 日常控制

### 7.1 局域网

手机和网关位于同一家庭 WLAN 时，App优先使用本地接口。控制请求经 HMAC、防重放和设备路由后才进入驱动；只有真实驱动读回、门磁或 UART ACK 确认后才显示成功。

家庭 WLAN 可以在无互联网时继续工作。验证时应断开路由器 WAN，保留手机和 ESP32 在同一 WLAN；关闭手机 Wi-Fi 不是局域网断网测试。

### 7.2 云端远控

在“我的/设置 → 云端配置”填写与实际 IoTDA 区域、项目、产品和设备一致的参数，并安全保存访问令牌。网关必须启用 IoTDA MQTTS。

手机使用蜂窝网络时，链路为：

```text
App HTTPS → IoTDA → 网关 MQTTS → 真实驱动 → 命令响应/属性上报 → 设备影子 → App
```

IoTDA 接受命令不等于设备执行成功。App 必须取得本次命令的 `reported_state` 或不早于本次下发时间的设备影子；超时、旧影子或设备离线应显示失败/未确认。

## 8. 各类设备的状态含义

- **门锁**：启用门磁时，以门磁到达目标位置为成功依据；反馈缺失或不一致不得显示“已上锁”。
- **灯光**：亮度 0～100 对应真实 PWM 输出；快速拖动时约每 55 ms 合并下发一次，只保留一条在途命令和最新目标值，使实体灯连续变化且不会形成命令积压。亮度为 0 时电源状态同步为关闭，调回非零值时自动开启。
- **UNO R4 RGB 测试灯**：App 不能直接访问 R4。网关使用签名 TCP 下发命令并等待 R4 的完整物理状态 ACK；R4 的旋钮和心跳通过签名 UDP 主动上报，网关认证后进入设备库存，App 通过状态同步更新颜色控件。
- **SHT30**：只有 CRC 正确的真实采样才显示；连续失败后应离线，不显示固定演示值。
- **PIR**：人体触发由网关本地开灯，无需云端；无人达到配置超时后关灯。期间 App 手动调灯会结束本次 PIR 自动控制权。
- **人体状态追踪**：PIR 会作为独立 `Presence_01` 出现在设备页，显示“检测到有人/当前无人”。绑定网关后，经过 HMAC 验证的完整设备清单会自动纳管，无需逐台点击添加。
- **自动化来源**：设备页显示物理传感器、设备反馈、手机局域网/云端或本地自动化；自动化还会显示规则 ID 和触发传感器。当前详情页、首页和设备页分别约每 350 ms、600 ms 和 1 秒刷新可见状态，全局网关同步约每 1.2 秒检查；远程影子通常按约 10 秒周期收敛。
- **温度联动**：启用网关的温度→空调规则后，高温/低温回差在网关本地判断；只关闭规则自己开启的空调，手机手动操作优先。空调 ACK 失败时不得显示成功。
- **空调**：网关只负责 UART 桥接，红外/原生总线由独立下位机实现。只有版本、target、requestId 匹配且含完整状态的成功 ACK 才能更新状态。
- **在线/离线/未知**：在线表示相应驱动或握手当前可用，不代表所有历史命令都成功；离线和未知不能用缓存绿色状态替代。

## 9. 空调下位机接口

ESP32 每行发送一条以换行结束的 UTF-8 JSON：

```json
{"version":"1.0","requestId":"req-123","target":"AC_01","brand":"GREE","action":"SET_TARGET_TEMPERATURE","value":25}
```

下位机真实执行完成后返回：

```json
{"version":"1.0","requestId":"req-123","target":"AC_01","resultCode":0,"message":"executed","state":{"power":true,"targetTemperature":25,"mode":"COOL"}}
```

海尔、格力、美的必须分别取得 ACK 与实体动作或协议分析证据。只更改 `brand` 字符串、App 卡片名称或本地状态不算多品牌实控。

## 10. 重置与故障处理

| 现象 | 检查与处理 |
|---|---|
| 找不到 BLE 网关 | 确认首次启动或已重置配网；靠近开发板；检查蓝牙权限和串口广播日志 |
| 家庭 Wi-Fi 列表为空 | 确认 PoP 正确、网关支持的 endpoint 完整、路由器 2.4 GHz 已开启 |
| 配网成功但扫描不到网关 | 手机回到同一 WLAN；检查 AP 隔离、防火墙、mDNS/UDP 和网关 IP |
| 网关探测通过但不能绑定 | 检查 HMAC 密钥、网关协议版本和板载 LED 真实 ACK |
| 本地控制失败 | 检查设备是否由网关发现、GPIO/驱动是否上线、手机与网关是否同网 |
| 云端控制失败 | 检查 IoTDA 区域、设备在线、`mqtts://`、证书、系统时间、Token 和设备影子时间 |
| SHT30 离线 | 检查供电、共地、SDA/SCL、上拉、电址 0x44/0x45 和 CRC/超时日志 |
| PIR 不动作 | 检查有效电平、预热时间、灯光 PWM 驱动是否上线和手动控制优先级 |
| 空调一直离线 | 检查 UART TX/RX 交叉、共地、电平、波特率、下位机握手和 ACK requestId |
| 路由器密码改变 | 网关固件正常运行时长按 BOOT 约 5 秒，看到提示后松开；网关重启进入 BLE 配网 |

“运行时长按 BOOT 重置配网”与“上电时按住 BOOT 进入下载模式”不同。重置时必须先松开 GPIO0 再重启，避免进入 ROM 下载模式。

## 11. 安全与隐私

- 局域网 HMAC 提供身份、完整性和防重放，不提供 HTTP 内容机密性；正式网络需要内容保密时应增加 HTTPS 和证书固定并重新联调 App。
- BLE Security1 保护配网传输；只有同时启用并验证 Flash Encryption/NVS Encryption 后，才能宣称 Wi-Fi 凭据在 Flash 中静态加密。
- IAM Token 不应烧录网关。联调临时 Token 用完后应立即撤销；正式产品应由受控业务后端签发短期权限。
- 设备 Secret、PoP 和 HMAC 密钥按设备分配、定期轮换，禁止所有网关共用仓库示例值。

## 12. 发布前

发布 App 或网关固件前至少完成以下复核：

- 在目标 OpenHarmony/HarmonyOS 设备安装签名 HAP，回归首次启动、权限、系统返回键和中英文切换；
- 对每种真实外设执行控制、状态回传、断网恢复和本地自动化测试；
- 对局域网 HMAC、BLE Security1、MQTTS、错误密钥和重放拒绝进行安全回归；
- 清除正式 PoP、HMAC 密钥、IAM Token、IoTDA Secret、签名私钥、日志和抓包，再生成公开发布包。
