# YaoCore 网关接口协议

本项目网关为正点原子 ESP32S3M 开发板，运行 **ESP-IDF 固件**；它不是 OpenHarmony 网关。OpenHarmony/HarmonyOS 适配发生在 ArkTS App 侧，两种运行时的 HAP 应按各自 SDK 配置单独构建和验证。

仓库中的源码、静态测试和 Python 协议桩只用于实现检查与联调，不能替代指定板卡上的编译、烧录和实物证据。最终结果必须以提交版本的日志、连续视频和设备状态 ACK 为准。

## 1. 网关发现与身份确认

网关通过 mDNS 发布 `_yaocore._tcp`，同时在配置端口监听 UDP 发现请求。UDP/mDNS 只用于定位候选地址，不能作为最终身份凭据。

`GET /discover` 返回协议版本、网关身份、安全能力和子设备真实状态，字段以 `protocol/discover-response.schema.json` 为准。App 要求协议 `2.0`、服务 `SmartHomeService`、算法 `HMAC-SHA256`、KeyId `app-key-v1` 和有效设备列表，并校验挑战值、请求签名、响应正文签名及 BLE 会话内取得的 `gatewayId`。正式 App 会拒绝带 `X-YaoCore-Simulator: DEV-ONLY` 的开发桩响应。

## 2. App 控制接口

`POST /control` 接收 `protocol/local-control-request.schema.json` 定义的命令。网关必须先完成结构、时间窗口、KeyId、HMAC 和防重放校验，再交给设备路由器。

控制成功同时要求：

- HTTP 状态成功；
- `result_code` 为 0；
- `request_id` 和 `seq` 与请求匹配；
- 响应 HMAC 与正文哈希正确；
- `reported_state` 包含该设备类型要求的完整最终状态；
- 实际驱动读回、门磁或下位机 ACK 已确认。

HTTP 2xx、本地缓存变化或“已经发送厂商帧”本身都不代表执行成功。签名 canonical form、JSON 原子编码、120 秒时间窗、300 秒 nonce 缓存和精确重传规则以 `protocol/README.md` 为准。测试向量中的公开密钥不得用于设备。

## 3. 统一设备路由

网关维护稳定身份到驱动的注册表。物理身份使用 `(gatewayId, deviceId)`，外部模块另有唯一 `moduleId`；名称、品牌和房间不是主键。

支持的主要能力如下：

| 类型 | 状态 | 动作 |
|---|---|---|
| door | open | OPEN, CLOSE |
| light | power, brightness, color | ON, OFF, SET_BRIGHTNESS, SET_COLOR |
| sensor | presence 或 temperature/humidity | 只读主动上报 |
| ac | power, targetTemperature, mode | ON, OFF, SET_TARGET_TEMPERATURE, SET_MODE |
| curtain | position | OPEN, CLOSE, STOP, SET_POSITION |
| fan | power, speed | ON, OFF, SET_SPEED |
| speaker | power, volume | ON, OFF, SET_VOLUME |

未知 target、未知动作、越界参数和不支持的能力必须明确失败。品牌适配器把统一能力转为 GPIO、PWM、红外、UART、RS-485、Zigbee 或厂商协议，但必须获得实体读回或厂商确认。

当前源码包含门控 GPIO 与可选门磁、LEDC PWM、SHT30 I²C、PIR 本地联动和空调 UART 桥。存在代码路径不代表外设已经实测。空调只有在下位机返回版本、target、requestId 和完整状态均匹配的结构化 ACK 后才能成功；只改变 `brand` 字符串不构成多品牌实控。

## 4. 外部模块接口

外部 Wi-Fi 模块首先调用：

```text
POST /module/v1/register
```

注册内容包括 `moduleId`、`deviceId`、设备能力、命令端口、命令路径、心跳周期和初始状态。网关把模块路由绑定到注册连接的来源 IPv4，正文不能指定任意下行主机。

网关向模块下发命令、模块返回物理 ACK 时使用带独立模块 HMAC 的 TCP HTTP。已注册模块的主动状态和心跳可以发送签名 UDP `YAOCORE_MODULE_EVENT`；网关完成模块身份、时间窗、nonce、HMAC 和单调序号校验后才更新库存，并返回签名 `YAOCORE_MODULE_ACK`。

连续三个心跳周期未收到有效 ACK 时，模块应保持稳定身份并重新发现、注册。完整正文和派生密钥规则见 `docs/EXTERNAL_MODULE_PROTOCOL.md`。

## 5. IoTDA 云接口

网关使用 MQTTS 和设备级凭据连接 IoTDA，订阅 `SetDeviceStatus`，把云命令映射到同一设备路由。执行器 ACK 成功后，网关响应命令并上报 `SmartHomeService` 属性和动态设备库存。

App 通过 HTTPS CreateCommand 下发并通过命令结果或新鲜设备影子收敛状态。IoTDA 接受请求、旧影子或网关缓存不能确认本次设备执行。IAM Token 不应烧录到网关；正式部署应使用受控后端提供的短期权限。

## 6. 快速验证项目

1. 无 WAN 但保留 WLAN 时，App 能发现、认证并控制网关。
2. 灯执行 ON、连续亮度、颜色和 OFF，ACK 与实体状态一致。
3. 旋钮改变灯色后，经签名 UDP 到达网关并同步 App。
4. 执行器断电时控制明确失败；恢复后模块自动重新注册。
5. 篡改签名、复用 nonce、过期时间戳和错误模块 ID 均被拒绝。
6. 丢失首次 ACK 后进行精确重传，设备只执行一次。
7. 传感器规则在 WAN 断开时仍能经统一路由控制执行器。
8. 云端实测时使用蜂窝网络完成 App→IoTDA→网关→设备→影子→App 全链路。

每项应记录日期、手机和系统版本、固件版本、网络拓扑、时延、结果及原始证据。没有对应证据的功能必须标为未测。
