# 隐私与本地配置

YaoCore 的公开仓库只保存源码、协议、无秘密模板和可复现的构建基线。Wi-Fi 凭据、设备密钥、云端 Secret、签名材料和现场网络信息必须只保存在开发者电脑、手机安全存储或实体设备中。

## 不会提交的本地文件

| 本地文件或目录 | 内容 | 公开替代文件 |
|---|---|---|
| `gateway/esp32s3m/sdkconfig` | 网关 PoP、HMAC 密钥、IoTDA Secret、GPIO 和本机构建选择 | `gateway/esp32s3m/sdkconfig.defaults` 与 `main/Kconfig.projbuild` |
| `devices/**/config.h` | 灯具 Wi-Fi、唯一设备身份和逐模块密钥 | 同目录的 `config.example.h` |
| `/build-profile.json5` | 本机 SDK、产品和签名选择 | `config/build-profile.*.template.json5` |
| `signing/`、`*.cer`、`*.p12`、`*.pem`、`*.key` | App 或服务端签名材料 | 不提供真实值 |
| `.env`、`*.token`、`*.secret` | 云端和开发环境凭据 | 可选 `.env.example` |
| `.hvigor/`、`**/build/`、`dist/`、`*.hap`、`*.bin`、`*.elf` | 工具生成的缓存、安装包和固件 | 使用源码重新构建 |
| `gateway/esp32s3m/managed_components/` | ESP-IDF 依赖管理器下载的第三方源码 | `main/idf_component.yml` 与 `dependencies.lock` |

`dependencies.lock` 应提交，用于锁定依赖版本；`managed_components` 不提交，因为 ESP-IDF 会按锁文件重新下载。协议目录中的测试密钥是公开互操作测试向量，代码会明确标注 `PUBLIC_TEST_SECRET`，不得用于真实设备。

## 新环境创建本地配置

### HarmonyOS App

```powershell
Copy-Item config/build-profile.harmonyos.template.json5 build-profile.json5
```

随后在 DevEco Studio 中选择本机 SDK 并配置自己的调试签名。证书和签名文件不要复制到公开目录。

### ESP32-S3 网关

```powershell
cd gateway/esp32s3m
idf.py set-target esp32s3
idf.py menuconfig
```

在 `YaoCore Gateway` 菜单为每台网关设置独立 PoP 和至少 16 字节的 App/网关 HMAC 密钥。启用 IoTDA 时再填写该设备自己的 URI、设备 ID 和 Secret。生成的 `sdkconfig` 只留在本机。

### UNO R4 WiFi 灯具

```powershell
Copy-Item devices/arduino_rgb_light/YaoCoreRgbLightUnoR4WiFi/config.example.h `
  devices/arduino_rgb_light/YaoCoreRgbLightUnoR4WiFi/config.h
python tools/derive_module_key.py module.standard.rgb.01
```

将 Wi-Fi、唯一 `moduleId`、唯一 `deviceId` 和派生模块密钥填入 `config.h`。每个实体模块都必须使用不同身份和密钥。

## 提交前检查

```powershell
git status --short --ignored
git check-ignore -v gateway/esp32s3m/sdkconfig
git check-ignore -v devices/arduino_rgb_light/YaoCoreRgbLightUnoR4WiFi/config.h
git diff --cached --name-only
```

暂存列表中不应出现 `sdkconfig`、`config.h`、证书、HAP、固件、构建目录或现场抓包。还应搜索现场 SSID、IP、邮箱之外的账号、Token、Secret 和密码；测试向量只能使用公开测试值。

如果秘密曾经进入 Git 暂存区但尚未提交，执行：

```powershell
git restore --staged <file>
```

如果秘密已经推送，无论之后是否删除文件，都必须立即轮换 Wi-Fi、PoP、HMAC、云端 Secret 和签名凭据；必要时再使用 `git filter-repo` 清理历史。仅删除最新提交不能使旧秘密失效。

## 设备与 App 数据清除

- App 中删除网关只解除本机绑定并清除相应安全存储，不会擦除实体网关。
- 网关运行时长按 BOOT 只清除 Wi-Fi 凭据。完整移交或报废时应执行 `idf.py erase-flash`，重新烧录后使用全新的 PoP、HMAC 和云端凭据。
- UNO R4 的 Wi-Fi 和模块密钥编译在私有固件配置中。移交设备前应烧录不含旧凭据的新固件并轮换原凭据；EEPROM 中的防重放序号不属于认证秘密，但可在受控维护程序中单独清零。
- 手机卸载 App 或清除应用数据可移除 Preferences 与 Asset Store 中的本地资料；正式移交前仍应在云端撤销旧设备和 Token。
